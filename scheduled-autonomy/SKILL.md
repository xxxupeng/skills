# 定时目标推进

持续保存目标；有工作时推进，等待外部结果时结束推理，由当前宿主机后台计时器唤醒原会话。
不是原生 `/goal`，也不是创建另一个会话。安装或讨论本 Skill 不等于授权启动目标。

## 目标合同

先读取当前项目指令和本会话已保存的目标。沿用明确的用户授权；缺少目标、验收、资源边界或截止时间时补齐必要信息，
不要为常规已获授权步骤重复确认。具体实验和机器约束来自项目，不写死在本 Skill。

用原生 `get_goal`（若可用）核对原生目标状态；若仍 active，先让用户在产品界面暂停/关闭原生 goal。
不要用虚假的 complete/blocked 将其关闭，也不要同时维持两个续轮机制。

可自主更新进展、证据、假设和授权内下一步；改变目标、验收、权限、截止时间须有用户明确授权，使用 `revise` 留痕。
更新计划/恢复/用户插问不重置原始预算。等待实验是 `waiting`，不是受阻。

## 每轮决策

- 有可立即完成的有效工作：继续做，不为每个小步骤安排计时器。
- 依赖长任务：记录实验身份、固定预计总时长、已检查次数、证据路径和判断分支；安排一次合理的唤醒，结束本轮。
  训练默认至少一小时，且不少于固定预计总时长的 1/10，最多十次常规检查（含完成核验）；更严项目规则优先。
  其他任务按实际耗时和用户频率约束选择间隔。不要以不断变短的剩余时间或上下文压缩重置计数。
- 醒来仍运行：只做必要健康/进度核验；正常且无重要变化时不重复汇报。合并健康检查和效果检查。
- 完成：分析固定指标与可视化，更新证据；在授权和剩余窗口内推进有依据的下一步，不因资源空闲而随意增加实验。
- 出错：按已有授权诊断/恢复；需要新权限或用户选择时 `wait-user`，说明最小阻塞。
- 目标达成、用户叫停、预算到期：`complete` / `cancel` / `expired`，停止后续投递。不自动终止已运行实验；实验生命周期单独授权。

### 按实际状态推进，避免空等

唤醒时间是检查计划，不是下一步工作的最早开始时间。最小检查间隔约束对仍运行任务的例行轮询，
不要求结果分析、已获授权的后续工作或用户主动查询等到原定时刻。
用户或事件提前唤醒后，若已确认任务完成，立即分析并推进有依据且获授权的下一步；若无外部依赖且有有效工作，
继续执行，不为满足检查间隔人为安排空等。仍在正常运行则保留合理检查间隔，不借此恢复高频轮询。
任务、下一步或预计耗时实质变化时，核对现有 pending：替换失效的时间/prompt，或在收尾/暂停时清除；
仍适用的唤醒保持不变。只在需要等待外部结果时安排新的延迟检查，始终最多一个 pending。
调整唤醒不延长探索截止时间、不扩大权限，也不因资源空闲而启动缺乏依据的实验。

每轮结尾判断“保留已有唤醒 / 新安排 / 替换 / 不再安排”。概念问答不机械重建定时器，不自动顺延检查时间。
一个会话最多一个 pending；多会话分别有自己的目标和计时器。不要调用模型短 sleep 循环等待。

## 运行

先读 [references/operations.md](references/operations.md)，执行脚本 `--help`。
`scripts/scheduler.py` 使用当前 `CODEX_THREAD_ID`、当前宿主的用户 socket，并核对项目路径；没有 ID 时不能用 `--last` 猜。
目前后端为 Linux + systemd 用户服务 + Python3/websocket-client；其他系统先报告后端未适配，不声称普遍可运行。
初次启动先 probe；优先复用现有受支持接口，不启动新 app-server，不用独立 `codex exec resume` 操作同一任务。

唤醒 prompt 写清：检查哪个任务/证据，正常未完成如何等待，完成如何分析和推进，异常如何处置，以及授权与停止条件。
后台消息是先前授权的调度，不是新用户授权。未来轮次必须读本 Skill 和目标文件。

`schedule` 成功只说明后台调度已安排；`accepted` 是服务接受，不等于任务完成。查投递记录/实际回复再报告唤醒成功。
`notLoaded` 是可恢复状态：核对ID/宿主/cwd后通过当前服务 `thread/resume` 加载同一会话并订阅事件，不创建新会话。
保留原始会话状态；非忙碌的临时错误也有界重试。投递后保持连接观察 `turn/completed`，最多30分钟/截止时间。
本轮必须安排后继或显式结束/暂停目标；完成却没有后继会标记待核对，不能让active空转到截止。
无需在每轮显示固定模板；有新安排时简述时间和目的即可。失败需说明，不能承诺自动恢复。

## 已知边界

持久化状态不代表计时器跨重启存活；重启后核对服务再恢复。桌面动态工具依赖原客户端时仍可能要求桌面保持连接。
忙碌只做后台状态检查（无模型），最多延后一小时；发送结果不明不重发，进入等待用户，避免重复行动。
失败保存 `ALERT.json`、journal与状态，尝试本机notify-send；这不是可靠的跨SSH桌面通知，`submitted`也不是阅读回执。
后台无法连接服务且没有可用通知通道时，无法保证主动告知用户；启用时必须披露，不承诺无人值守故障必达。
idle 检查与 turn/start 不是原子接口，极短竞态仍可能与用户消息相遇；不会主动 steer/interrupt。
预算到期禁止新投递，但不会强行中断已经开始的模型轮次。轮次开始和启动新实验前都重新检查截止时间。
